# M1.c：冷却与动作历史

2026-10-26。完成 M1.c1–c3 的数据重建、规划约束和接受记录语义；不开放建议采纳/压缩执行 UI，不启动模型请求，不实施 M1.d/e 的载荷与执行功能。

## 按窗口重建，不维护重复计数器

`resolve_context_inputs_cmd` 继续只读：从当前窗口的持久化 turn/message 投影，结合现有 SQLite `context_actions` 的接受记录重建冷却。不新增计数表、迁移或新的写 IPC。重复查询、组件重挂、事件重放、应用重启不会额外递增，也不会给 CONTINUE 单独造动作记录。

- runtime 只把 `Completed + cleanupConfirmed + 无 error` 的结束轮次计为 CONTINUE。失败、取消、清理未知、在途轮次不计；保留它们作为上下文观察，并不伪装成功。
- 使用 M1.b 的窗口/Provider/请求与实际模型/角色/task 隔离。相同结束时间保留已有持久事件顺序，不按随机 UUID 重排；完成 ID 去重后再计数。
- 旧 Direct 会话从正常 thread 事件给每条助手消息保存 `nativeThreadId/nativeThreadSessionId`，随现有消息 JSON 持久化。只拼接同所属会话、窗口、模型和模式的记录。复制到其他会话的消息不借用原计数；缺字段历史不根据 conversation 当前 thread 回填。
- 截断到 512 条、缺少可证明的旧窗口归属或旧协议未传完成标记时，冷却保持未知/保守的 0，不把部分历史当完整证据。返回 `cooldown.known/source`，UI 显示未知原因；不会称已经实测为 0 轮。

`turnsSinceLastCompact` 进入真实 `InWindowContextParams`，不再沿用 M1.b 占位 0。无接受记录时，从窗口开始的已证实完成轮次计数；有接受记录时，仅统计最新接受锚点之后的成功完成轮次。默认/缺字段在 Rust 与 mock 中均为 0，不默认虚构已经完成 5 轮。

## 采纳后重置

沿用现有 Storage 的动作写入/状态更新 API：SUGGESTED → APPLIED 持久化接受时间，即重置边界。COMPACT/FRESH 才重置；SUGGESTED、DISMISSED、未采纳就 FAILED、REUSE 以及独立 CONTINUE 动作行不增加/重置计数。

重建时通过参数绑定只读取当前完成 ID 的源/目标记录，FRESH 的 `new_attempt_id` 可将重置归属到新窗口。若动作有承载模型 turn，后续执行入口须在开始前把它绑定为目标 ID，该承载 turn 不计 CONTINUE；无目标时以源锚点为边界。若旧建议迟到采纳，接受时间之前已结束的轮次不能被追认成冷却之后的进展。

相同 APPLIED 重试保留原接受时间；目标 ID 允许从空绑定一次，不允许改成另一个目标。终态不能用原动作 ID 重新 APPLIED，需新动作记录。曾经采纳、随后 UNDONE/FAILED 的记录仍保留原冷却边界，不能通过撤销或失败立即绕过间隔；这不是声称动作已经成功执行。无有效接受时间的 APPLIED 记录令解析不可用，不用“现在”修补历史。

存储读取有边界并去重，来源/目标同时命中不重复。SQLite 使用现有 writer 事务更新状态，读预览不写动作状态或接受时间。

## 两轮间隔与硬上限

0/1 个成功 CONTINUE 时，经济性建议不能再次 COMPACT/FRESH；2 个以后才解除该约束，是否建议动作仍由成本与上下文判断决定。普通刷新、点击、审批本身以及纯等待不会推进计数。

修复原先硬上限分支绕过冷却的问题：若 CONTINUE 已因硬上限被禁用、COMPACT/FRESH 又在冷却，返回 `cooldownBlocked=true`、`continueDisqualified=true`，没有可自动执行的动作。为兼容既有枚举，recommendedAction 的 CONTINUE 只是占位，不能解释为获准继续。上下文栏显示冲突，建议组件不提供 Apply。Rust/mock 共用这一约束；正常成本示例显式提供已满足冷却的 2 轮条件，不靠默认值放行。

预览仍为 readOnly，不是执行授权。M1.e 的采纳/执行控制器必须在写入接受记录后重新解析，并绑定最新窗口/turn/授权；不得把缓存预览当作采纳凭据。这里完成后端重置/递增契约及生产只读接线，不声称当前 UI 已经能采纳并执行压缩。

## 验证与限制

离线覆盖重复查询/ID、0→1→2、采纳与重复 APPLIED、FRESH 目标、失败/未知清理、撤销后不能绕过间隔、不同窗口/复制会话、数据库重开、迟到采纳、同秒精度不足、旧缺字段/截断历史、硬上限冲突、前端阻断 Apply。持久化重开使用正常 Storage 写入/更新 API；固定时间仅写测试专用临时数据库。

持久 turn 完成时间只有秒级、接受时间为毫秒级：无法证明同秒完成晚于接受时，保守不计，不用 UUID 排序或墙钟等待补证据。动作表损坏/超限/时间不可解析时返回不可用，不以空历史放行。实际模型、CLI UI 的冷却行为与压缩成功仍待 M1.e/g 的正常外部 UI 验收。
