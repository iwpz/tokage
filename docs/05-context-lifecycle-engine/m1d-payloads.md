# M1.d：当前会话 COMPACT 载荷

2026-10-26。d1/d2 完成载荷对齐；后续 d3 补齐普通主会话显式采纳后的下一轮发送。预览仍只读，采纳不立即调用模型，原生压缩传输和自动采纳仍未开放。离线验证证明请求进入正常发送接口，不代表真实模型压缩成功。

## 来源和身份

现有 `resolve_context_inputs_cmd` 返回可选 `compactIntent`，沿用真实输入解析。后续新增 `prepare_compact_turn_cmd`，只在用户采纳并发送下一轮时重新解析、构造载荷并写接受记录；它自身不运行 CLI。Scope 绑定当前 session、完成 turn、window、provider、model、role、task 和 revision。Provider 来自当前请求的已选窗口身份，补齐 CODEX_CLI、CURSOR_CLI、COPILOT_CLI 正式标识；不写死 CLAUDE_CODE。

Runtime 主会话使用当前计划目标，缺计划时使用原始需求；任务窗只使用对应 task.goal。契约保留当前计划内真实 ID、标题和正文；PlanContract 没有物理文件路径，contractPaths 保持空，不编造路径。仅摘录所选窗口当前失败、当前任务错误和失败 Gate，不混入其他任务或恢复前的历史错误。缺任务、缺契约、同任务有未结束 turn 时不构造载荷。

旧会话只在消息的原生窗口所属会话、provider/model、mode 与当前 thread 一致且没有在途消息时构造；使用实际首条用户需求作为目标。缺可证明归属时不猜测、不从标题生成目标。错误限于最近成功之后的当前窗口，摘录去重并限制长度。

保留信息缺失或过期时单独返回不可用原因，仍保留有效的 token、成本与冷却预览。Rust 校验身份一致性、字段长度、错误/契约数量及整体保留数据上限。保留正文作为 JSON 数据，并明确不构成额外命令或授权。

## 方法分流与下一轮草稿

- NATIVE_SLASH_COMMAND：记录 command，保留内容进行单行 JSON 转义；transportReady=false，草稿构造器拒绝执行。原生命令语法候选不是当前已启用或实测的传输能力。
- INSTRUCTION_PROMPT：生成同窗口前缀草稿；用户原文独立保留，不改写用户消息。
- SYNTHESIZED_FRESH_BRIEF：生成保留简报草稿，requireNewWindow=true；不能把 resume 解释为新窗。Aider 不再把丢弃内容的 /clear 当作保留式压缩。

`compose_compact_turn_draft` 同时检查完整 scope 和保留数据相等；目标、错误、契约改变即失效，即使旧协议没有 revision。草稿本身仍 readOnly，不是模型执行结果。生产接线使用每个 Conversation 自己的 pendingCompact，不再使用全局字符串；普通主会话的正常 send 接口负责派发，不更改权限或模型选择。

普通主会话中，仅有可用 COMPACT 建议、冷却已知且解除时显示“下一轮应用”。用户采纳后显示“已排队、尚未执行”，可取消；不自动发模型请求。发送时再次检查当前窗口、保留数据、模型、模式、工作目录、具体启动参数、项目信任和上下文设置，并重新运行后端输入解析和规划门禁。缺少具体启动参数的历史记录必须先完成普通一轮，不能猜测连续性。取消或状态在准备期间变化时停止派发；未发送的原文放回正常消息队列。

指示型载荷作为前缀进入 startChatTurn，继续同一原生窗口；新窗型载荷使用 resume=null、fork=false、history=[]，不把旧历史重新塞入新窗。用户原文在对话中保持不变，CLI 的具体模型和启动参数保持原值，权限沿用普通发送路径。独立提问不消费 pending，切换会话或 fork 也不带走源会话的 pending。

prepare 接口从重新解析的当前意图生成前缀，不使用调用方提供的 prompt。通过门禁后持久化 COMPACT 接受记录并绑定承载消息 ID，供 M1.c 冷却重建排除该承载轮。APPLIED 仍仅表示接受，不是执行成功；即使后来取消或发送失败，也不能把接受历史删掉以绕过冷却。排队状态仅存在当前会话的内存中；退出后丢弃，需重新采纳，不承诺跨重启恢复。发送时写入的接受记录才会持久化。

移除旧全局 pending/settle 消费路径及无生产调用的 settle IPC。旧逻辑会把未知实际费用视为 0，并用多轮基线减单轮费用；本次不写 actualSavingUsd 或 CONTEXT 节省事件，新口径交给 M1.f。没有为了接线增加自动授权、模型切换或运行时测试例外。

当前开放范围是普通主会话的显式采纳。Runtime/任务窗仍只有只读预览，不通过普通 chat 绕过共享 runtime；自动采纳、原生传输、共享 Runtime 的接入及真实 UI/模型验收继续由 M2/M3/M1.g 完成；普通主会话的失败和结果提示见 [M1.e](m1e-execution.md)。M1 整体验收未完成。
