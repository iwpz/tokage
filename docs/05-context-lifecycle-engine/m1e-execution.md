# M1.e：普通主会话执行路径

2026-10-27。M1 采用显式采纳后的下一轮前缀：同窗指示随用户下一条原文发出；新窗简报以 `resume=null`、`history=[]` 发出。采纳只排队，真正发送仍使用正常 `startChatTurn`、模型参数和授权流程。保留简报不是可证明的原生压缩，不推断 token 减少或节省。

## 原生与可见反馈

有原生 slash command 的建议显示“需要 M2 原生路径”，不提供采纳按钮，也不将命令作为普通聊天文本发送。自动采纳和原生适配器仍待 M2。

采纳时追加本地系统消息并显示可取消排队提示；该消息不发送给模型。承载轮成功结束时追加“保留信息已随本轮请求发送，且本轮已结束；实际上下文缩减尚未确认”；这是发送与轮次完成证据，不证明模型遵循指示或者执行了原生压缩。启动失败、流式错误、取消时分别提示未确认生效；记录更新失败也提示用户。系统消息不会混入后续发送的模型历史。

消息关联 `compactAction` 的 action ID、方法和状态；开始后为 running，完成、失败和取消分别记录，不同会话不会消费彼此动作。应用重启时，尚未结束的承载轮标为 unknown，并在消息中说明效果未知。待发送的排队状态只保存在当前进程内；包括本地存储降级恢复时都会丢弃，必须重新采纳。

## 接受记录与失败

准备时重新解析当前规划与冷却，并校验 scope、原始保留数据、模型、模式、工作目录、具体启动参数和项目信任。插入建议和绑定承载消息并转为 APPLIED 在存储 writer 的同一事务中完成。APPLIED 表示已接受，不表示完成或成功。

若准备完成后又取消或状态改变，已接受记录变为 UNDONE；启动失败、承载轮出错或停止时变为 FAILED。更新只允许与记录绑定的承载消息，终态不能重新激活；已接受时间保留供 M1.c 保守冷却计算。发送前再次检查信任与上下文开关，取消和完成竞态不会把已完成轮覆盖成取消。若 RPC 在数据库提交后丢失响应，客户端可能无法获知 action ID；该记录仍按接受状态保守参与冷却，不能推断已发送。

正常运行中前端显示与记录更新是分别进行的：保存失败会报告，而不是伪称数据已持久化。应用突然退出时，尚未收齐事件的承载轮效果未知，不能追认为成功；本节点不补造成功或成本。

## 范围与证据

此路径只适用于普通主会话。共享 Runtime 当前没有通用主会话追加消息命令，因此继续只读预览，不绕过 Runtime 的状态机、授权与持久化。任务窗、自动模式、原生命令与跨重启恢复分属后续节点。未新增节省结算；M1.f 需建立可比口径。M1.g 的真实 UI 和模型验收仍未完成。

离线测试覆盖两种载荷、原生路径不开放、排队与完成显示、启动失败、模型错误、取消、完成/取消竞态、重启未知状态、目标消息绑定与冷却锚点保留、系统消息不进入历史。测试使用正常 IPC 边界的单元模拟，不作为真实模型、CLI 或桌面 UI 证据。
