# M2.a：自动排队与持久撤销

范围：普通主会话中已经可执行的 COMPACT 指示/新窗保留路径。自动排队不是自动发起模型调用；没有用户发送消息时不执行额外推理。FRESH 独立建议、热缓存进展报告、原生 slash、共享 Runtime/任务窗口仍属于 M2.b/c 或 M3，不据此勾选 M2 整体。

## 行为

- `off`：不规划、不自动排队。`suggest`：需要点击采纳。用户主动选择 `auto` 后，界面出现可执行的 COMPACT 预览即可自动排队；即使消息在界面 effect 完成前发出，普通发送也会等待/补做相同排队校验。
- 排队重新解析当前窗口、历史与保留信息，数据库写一条 SUGGESTED；自动记录 trigger=PLANNER，手动记录 USER。排队不创建派发目标、不产生冷却锚点。
- 撤销立即清除会话 pending 并抑制来源轮次自动重排，数据库将未派发建议设为 UNDONE。规划查询读取相同来源/会话最近的队列回执，重开会话后仍识别撤销。手动重新采纳可创建新建议；新的完成来源轮次可重新自动规划。
- 下一条普通用户消息发送前重新解析、验证模型/启动选项/工作目录/信任/模式，原子地把同一 SUGGESTED 记录更新并绑定为 APPLIED。费用基准使用发送前的最新首轮估算。已撤销或已消费记录不能绑定给另一个目标。
- 排队写入期间撤销、模式关闭或权限失效时，迟到回执会被 UNDONE；承载准备期间撤销则用目标绑定的既有失败命令标为 UNDONE。队列写入失败不会发模型，原用户正文留在普通消息队列中。
- 自动模式切为 suggest/off 时，界面撤销自动排队；发送端也重新检查。审批续接显式标为内部消息，不消费用户上下文动作；一次性隔离问答同样保留动作。
- 无关系统提示不会仅因会话对象换了引用而撤销准备。比较当前 pending 与实际输入快照，并保留准备期间产生的无关提示。规划新窗的保留前缀放在渲染后的规划模板外，原用户消息不与前缀混成同一个模板参数。

## 默认与迁移

设置 v7 保持默认 `off`。v6 及之前的 `auto` 实际依赖手动采纳，因此迁移为 `suggest`，避免升级后静默改变其执行语义；原有 off/suggest 保留，v7 后主动选择的 auto 保留。设置 UI 与中英文文档说明此迁移，不修改个人全局配置。

## 状态及边界

队列回执仅有 SUGGESTED/UNDONE 时不进入上下文冷却；绑定承载轮后沿用已有冷却、失败/取消及首轮反事实结算。中断后未完成的动作不追认为已执行。若持久化撤销失败，UI 明确报回执失败，不能宣称 UNDONE 已落库。后台/窗口关闭导致排队 IPC 回执丢失时，不推断执行成功；数据库中未消费的 SUGGESTED 不自动变为 APPLIED。该节点没有新增全自动授权、付费后台摘要或厂商压缩能力声明。

M2.a 的 UI/发送/存储契约已经离线覆盖。真实桌面 auto→撤销→发送及跨重启仍留给 M2.e；M1 的手动采纳实机记录不代替本版验收。
