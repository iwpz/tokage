# M2.b：FRESH 进展与新窗承载

`M2.b-local` 实现普通主会话的 FRESH 排队、新窗首包、已有报告复用/本地进展抽取。本节点 `M2.b-report` 补齐默认关闭、显式开启的热缓存额外报告轮及其取消、费用链路。未运行真实模型或桌面验收，不将 M1 的手动保留目标样本追认为本版 FRESH 通过。

## 进展来源

普通会话从当前原生窗口、会话、模型和角色已经筛选过的最近最多八轮构造进展候选。记录来源消息 ID 和最多 32 条变更路径；本地报告只使用用户请求、最后助手输出和近期错误的有界摘录，明确标为未验证摘录，不从文件路径推断测试通过或工作已完成。没有模型报告时，不生成一条假模型报告。

若最新成功助手输出包含按顺序排列且非空的五段：What was completed、Deviations from contracts、Hints for downstream、Self-check against acceptance criteria、Next step，并且长度不超上限，才作为“已有模型报告”候选。失败输出、工具/独立 reasoning、外部窗口和缺段报告不提升为模型报告。它仍是模型此前的声明，需要核验。

原生解析器根据当前缓存估价选择来源：热缓存优先完整模型报告：本次生成标为 `GENERATED_MODEL_REPORT`，旧报告标为 `EXISTING_MODEL_REPORT`；冷缓存或无可复用报告时标为 `LOCAL_EXTRACTION`。这不是为保持缓存发请求，也不证明厂商实际命中缓存。进展含最多八个来源 ID，最后一个必须是当前源消息；过期、缺失或超长材料拒绝。报告候选最多 32 KiB，本地抽取与已有模型报告前端另限 6000 个 Unicode 码点；`report_max_tokens` 用户设置及严格 token 预算仍属于 M3.e，不能把该字符上限称为已实现的 300-token 配额。

## 执行与状态

- FRESH 建议经手动/auto 的同一条队列路径，保存 kind=FRESH。缺当前进展证据不开放该动作，不因 Provider 存在原生 compact 候选而退回 slash。
- 新窗首包为保留目标/契约/当前错误的简报、带来源的进展报告、单独分隔的原样用户消息。只有选中的报告进入载荷，另一候选不随之发送。JSON 被标为不可信材料，不作为权限或可执行命令。
- 新窗使用统一的 `SYNTHESIZED_FRESH_BRIEF` 传输，清空 resume/history。原有 Codex/Aider 的合成 COMPACT 新窗路径也消费这份进展构造，不维护第二套新窗实现；老客户端无 progress 的 COMPACT 继续保留原目标路线。普通同窗指示和原生候选不隐式接收这两份进展候选。
- prepare 重新解析规划与冷却、校验动作身份，SUGGESTED→APPLIED 绑定同一条记录的 newAttemptId。UNDONE、失败/取消、跨 session 和目标重复绑定沿用 M2.a 的约束。FRESH 只允许 `method=fresh` 的承载元数据，不能把同窗指示结算为新窗动作。
- 完成后共用 `first_turn_counterfactual_v1`：报告前冻结的原窗同一首轮预计费用与“额外报告轮＋新窗承载轮”的报告费用比较，差额夹零；缺费用保持未知，不将重开窗口、局部摘录或模型声明当作实际账单节省。

## 热缓存额外报告轮

设置中的“生成热缓存进展报告”默认关闭，既有安装不会自动开启。开启后，仅在用户发送、已手动排队或 auto 可执行、缓存估计为热、当前无完整模型报告、目标采用新窗简报时生成一次；不会因预览刷新发起调用。同模型、启动参数、角色、目录、原生线程与项目授权均需连续，Debug Provider / 演示禁用。冷缓存、已有完整报告、开关关闭均沿用原有路径。缓存“热”为估价判断，不代表供应商命中证明。

额外轮使用正常 chat 传输，phase=CONTEXT，沿用原模型与权限，用明确的五段报告请求，要求不编辑、不执行命令、不开展新工作；提示词不是额外沙箱，原有权限控制仍有效。它不保存为规划成果，也不触发普通完成回调提前消费下一条用户队列。成功后重新解析建议、来源与冷却，保存并准备新动作，再原样发送用户消息到新窗。并发输入排队；报告完成本身不清除既有未解决错误。报告缺段/超长时只选有界本地摘录，不重试生成；已产生的报告费用仍保留。

Stop、报告失败/要求工具审批、关闭开关/模式、撤销信任或建议改变均停止交接，原消息留在队列；Stop 与迟到完成竞态也不能启动承载轮。取消旧排队记录后按报告源重新排队；生成来源记录原消息、报告消息及报告前估价参数。原生校验源消息确在当前窗口、报告消息为当前源、费用非负、估价参数可解析且非负；这些是普通会话持久化的报告来源，不是厂商账单认证。报告费用及新窗费用分别保存，任一未知则本次干预不结算。失败/取消而未交接的报告只保留正常用量，不生成成功节省事件。旧结算记录的重试明细保持兼容。
