# M2.b：FRESH 进展与新窗承载

本节点为 `M2.b-local`：实现普通主会话的 FRESH 排队、新窗首包、已有模型报告复用/本地进展抽取与首轮结算。它不发起专门的热缓存模型报告轮；该轮仍须单独完成费用、取消和权限链路后才能勾完 M2.b1。未运行真实模型或桌面验收，不将 M1 的手动保留目标样本追认为本版 FRESH 通过。

## 进展来源

普通会话从当前原生窗口、会话、模型和角色已经筛选过的最近最多八轮构造进展候选。记录来源消息 ID 和最多 32 条变更路径；本地报告只使用用户请求、最后助手输出和近期错误的有界摘录，明确标为未验证摘录，不从文件路径推断测试通过或工作已完成。没有模型报告时，不生成一条假模型报告。

若最新成功助手输出包含按顺序排列且非空的五段：What was completed、Deviations from contracts、Hints for downstream、Self-check against acceptance criteria、Next step，并且长度不超上限，才作为“已有模型报告”候选。失败输出、工具/独立 reasoning、外部窗口和缺段报告不提升为模型报告。它仍是模型此前的声明，需要核验。

原生解析器根据当前缓存估价选择来源：热缓存优先已有完整模型报告，标为 `EXISTING_MODEL_REPORT`；冷缓存或无可复用报告时标为 `LOCAL_EXTRACTION`。这不是为保持缓存发请求，也不证明厂商实际命中缓存。进展含最多八个来源 ID，最后一个必须是当前源消息；过期、缺失或超长材料拒绝。报告候选最多 32 KiB，本地抽取与已有模型报告前端另限 6000 个 Unicode 码点；`report_max_tokens` 用户设置及严格 token 预算仍属于 M3.e，不能把该字符上限称为已实现的 300-token 配额。

## 执行与状态

- FRESH 建议经手动/auto 的同一条队列路径，保存 kind=FRESH。缺当前进展证据不开放该动作，不因 Provider 存在原生 compact 候选而退回 slash。
- 新窗首包为保留目标/契约/当前错误的简报、带来源的进展报告、单独分隔的原样用户消息。只有选中的报告进入载荷，另一候选不随之发送。JSON 被标为不可信材料，不作为权限或可执行命令。
- 新窗使用统一的 `SYNTHESIZED_FRESH_BRIEF` 传输，清空 resume/history。原有 Codex/Aider 的合成 COMPACT 新窗路径也消费这份进展构造，不维护第二套新窗实现；老客户端无 progress 的 COMPACT 继续保留原目标路线。普通同窗指示和原生候选不隐式接收这两份进展候选。
- prepare 重新解析规划与冷却、校验动作身份，SUGGESTED→APPLIED 绑定同一条记录的 newAttemptId。UNDONE、失败/取消、跨 session 和目标重复绑定沿用 M2.a 的约束。FRESH 只允许 `method=fresh` 的承载元数据，不能把同窗指示结算为新窗动作。
- 完成后共用 `first_turn_counterfactual_v1`：原窗同一首轮预计费用与新窗承载轮报告费用比较，差额夹零；缺费用保持未知，不将重开窗口、局部摘录或模型声明当作实际账单节省。

## 尚待完成

热缓存且没有完整旧报告时，本版以明确标注的本地摘录执行，不追加隐藏付费请求。计划中“在旧窗口额外请求新进展报告”的热路径尚未实现，M2.b1 保持未完成。M2.e 必须另行以正常 UI 验证 auto 撤销、真实 FRESH 来源与新旧线程；M2.c 原生 compact 仍不启用。

## 验证

新增离线断言覆盖进展的窗口隔离、失败/空段报告拒绝、Unicode 有界摘录；原生报告来源选择、缺失/过期来源拒绝、契约/错误保留及禁用原生命令；手动与自动 FRESH 新线程请求、目标记录及相同结算入口。存储库原有“不接收未支持 FRESH”的断言最初失败，修复为继续拒绝无 method=fresh 元数据的 FRESH，并新增绑定/结算断言；没有删除该非法输入检查。


最终验证：前端全量 85 文件 / 552 项、上下文 43 单元 + 2 集成、存储 44 项通过；TypeScript/Vite 生产构建、桌面 crate cargo check、i18n（1902 键）、IPC 接线（141 个命令、未豁免无生产调用 0）和测试隔离/差异检查通过。前端最多 2 worker，Rust 2 编译 job / 2 测试线程。本节点没有运行真实模型或 normal-UI FRESH 验收；M2.b1 和 M2.e 不据离线结果勾完。
