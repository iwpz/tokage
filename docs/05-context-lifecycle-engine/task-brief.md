## 1. Task Brief

Fixed execution instructions are byte-identical and placed first; task-specific content follows.

```markdown
# Tokage Task Brief v1

## Execution rules
You are one executor in a multi-agent pipeline. Other agents work on other tasks in parallel; you cannot see their context.
1. Strictly follow interfaces, types, and conventions in the "Contracts"; if you must deviate, do not edit contracts yourself—note it in the report.
2. Modify only files within "Write scope."
3. After finishing, run "Acceptance commands" for self-check.
4. Finally output a "Task report" in the format at the end, no more than 300 Token.
5. Write the free text of the report in the same language as the task description. Keep the section headings and the word `None` exactly as shown, in English.

## Task
- ID: {{task.id}}  Domain: {{task.domain}}
- Title: {{task.title}}
- Goal: {{task.goal}}
- Deliverables: {{task.deliverables}}
- Write scope: {{task.write_scope}}
- Acceptance commands: {{task.acceptance.commands}}
- Acceptance criteria: {{task.acceptance.criteria}}

## Contracts
{{#each contracts}}
- {{id}} {{title}}: {{path}}
{{#if inline}}
{{content}}
{{/if}}
{{/each}}

## Upstream results
{{#each upstream}}
### {{task_id}} {{title}}
{{report}}
Changed files: {{changed_files}}
{{/each}}

## Failure evidence
{{failure_evidence}}   <!-- repair reassignment only -->

## Task report format
### What was completed
### Deviations from contracts (write "None" if none)
### Hints for downstream
### Self-check against acceptance criteria
```

## 2. Task Report

After the execution model outputs four sections, Tokage appends locally extracted parts; final stored in `task_reports`:

```markdown
## T1 User API · Done
Model: {{model}}  Execution window: {{attempt_id}}  First pass: yes

### What was completed
… (execution model output)

### Deviations from contracts
None

### Hints for downstream
…

### Self-check against acceptance criteria
- All status codes in C1 covered: yes

### Changes (local)
src/server/users/routes.rs   +120 −0
src/server/users/repo.rs     +64  −0

### Acceptance gate (local)
cargo test -p server users   passed (12 passed)
```

When the execution model does not output those four sections, the full report is generated by local extraction with no extra request ([03 §4.2](../03-orchestration-engine/README.md)).

Passed downstream: only “What was completed,” “Deviations from contracts,” “Hints for downstream,” and changed file list.

## 3. Progress Report (`FRESH` Action)

When in-window planning chooses `FRESH`, request one progress report in the old window first—same format as task report plus a “Next step” section—as content for the “Upstream results” slot in the new window brief. When old window cache is hot this turn is very cheap; when cold, fall back to local extraction (changed files + recent errors + user message excerpt).
