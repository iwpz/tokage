## 环境、辅助与失败保留

- 普通 release 构建使用标准 Tauri 配置叠加，隔离应用标识和原生数据目录，WebView 使用 `incognito: true`。这不是原发布二进制验收，也不证明前端设置跨重启持久化。CLI 使用现有账户，CLI HOME、凭据和缓存未隔离。
- 所有真实调用请求固定为 `CODEX_CLI / gpt-6-luna / medium`，CLI 版本为 `0.161.0`。桌面中通过正常设置选择已安装的 `/Users/iwpz/.local/bin/codex`。运行记录未提供独立的 observedModel 值和实际美元费用，均保持未知。
- 外部操作先使用系统 Accessibility 工具，中途使用 CUA；CUA 在会话中被停用后，继续用已有 Accessibility 工具操作同一普通界面。未注入页面 JavaScript，未修改 Store、数据库、确认处理或运行时授权逻辑。
- 原计划分场景使用不同 fixture checkout。文件选择器操作不稳定后，编排复用已完成直聊验证的干净独立 fixture，并通过正常显式重试在同一 run 中完成正常退出、SIGKILL、交付三个阶段。各阶段单独留证，不能把它们统计成三次独立需求成功。
- 首次逐段键盘输入的计划导入停留于 Draft，保留该失败尝试。随后通过普通粘贴导入，原生保存的 Markdown 与冻结文件逐字相同。另一次公开 CLI 导入仅用于无模型的诊断，不计入桌面通过证据。
- 并发设为 2，重试策略为 manual。默认 `blockUnknownCost=true` 在中断后的显式重试中阻止继续，且未新增 turn。为完成后续恢复验证，通过普通执行设置将其改为 false 并重新批准原计划和三条验收命令。SIGKILL 与待合并结果是在此已披露配置下取得，未知费用没有改成零。
- 所有中断尝试和工作区均保留。未修改模型实现代码来帮助它通过，未手工合并产物，最终合并由正常桌面交付操作完成。验收结束后正常退出隔离应用。

## 尚未覆盖

专用 OS 账户中的原发布包、持久 WebView 设置、其他系统和模型尚未验收。强杀后仍存活的子进程阻断窗口没有被捕获，不能由本轮推断该子情形通过。断电、磁盘损坏、数据库部分写入和更大规模任务也不在本轮覆盖范围。

这是一组可复核的恢复专项结果，不代表首次自主交付成功率，也不扩大历史 9/20 的统计口径。
