# m1b：任务报告与执行资料隔离实施记录

实施日期：2026-10-16。对应 [可靠性优化计划](可靠性优化计划.md) 的 m1b。

## 身份与读写规则

- 报告、brief、gate 使用 `sessionId + planRecordId + taskId`；`planRecordId` 是 `plans.id`，明确指向某个会话的某个计划版本，`taskId` 是该计划内的局部编号。数据库已有 `UNIQUE(plan_id, code)` 任务约束。
- V12 为三张资料表增加会话、计划外键、联合索引与 `association_status`。写入触发器检查计划所属会话、任务所属计划；报告必须有指向同一数据库任务的 attempt。gate 的可选 attempt 一旦提供，也必须匹配。保留旧 `gate_runs.plan_id` 字段，但新写入必须与数据库计划编号一致。
- 所有报告生产查询，包括恢复、重规划、交付汇总，必须提供完整身份；brief 的存储接口同样收紧。gate 查询必须提供会话及数据库计划，只允许进一步按任务筛选，不再支持全局局部任务号查询。
- attempt 的任务关联不能指向其他会话，也不能事后改变。结束执行时仍允许使用已有的“空会话 / 空任务字段，仅更新状态”协议。
- 动态插入的冲突修复任务在启动 CLI 前登记到当前数据库计划；继续执行、审批后恢复也登记新的 attempt。登记失败在桌面运行时阻止 CLI 启动。报告保存被拒绝时任务进入 `BLOCKED`，不继续提交或派发下游。

## 恢复、重规划与界面

- 流水线快照持久化并恢复 `taskDbIds`，避免恢复后将 attempt 错误写成无任务归属；动态登记也会重新确认数据库映射。
- 重规划更新 `planDbId` 和任务映射，并暂停等待继续。修改、移除或重新加入的任务清除旧线程、attempt 指针、报告、执行时间、失败证据和工作目录等运行资料；修改后的已完成任务重新进入 `PENDING`。旧 gate、审批授权和交付结论不会自动当作新版本的结论。
- 未修改的已完成任务可有意沿用：通过持久化的 `taskReportPlanIds` 明确记录原报告计划，查询仍同时检查当前会话和任务编号，不将旧 attempt 改绑到新任务。再次执行完成后去掉该来源指针。
- 重规划输入使用正确的完整报告 `fullMd`，不再以摘要代替。交付文件和成本从明确来源的报告读取。
- gate 面板只读取当前会话、当前数据库计划；切换时清空旧结果，忽略先前请求的迟到响应。
- 检查了其他执行资料：流水线中的 gate / upstream artifacts 按会话快照保存；审批与上下文资料使用会话 / attempt 身份；`task_outcomes.task_id` 虽保留局部编号，但只用于模型 / 领域聚合，不存在按它读取任务交付材料的路径。本次没有把学习统计扩展为任务执行证据。

## 历史迁移

- 不删除任何历史报告、brief 或 gate 行，不凭 `T1` 唯一性或当前打开的计划推测归属。
- 只有历史报告具备 `attempt → tasks.id → plans.id` 完整关联，且会话、任务编号一致，才标为 `BOUND`。历史 gate 还要求原计划字段与该数据库计划一致。
- 无法证明归属的行保留为 `LEGACY_UNASSOCIATED`，不进入自动报告 / brief / gate 查询。历史 brief 缺少证明链，全部保留为未关联。
- 无数据库计划身份的旧流水线不尝试通过局部编号回填报告；其会话快照中已有的资料仍保留。
