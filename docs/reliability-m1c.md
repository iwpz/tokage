# m1c：写入范围检查失败即阻塞

实施日期：2026-10-16。对应 [可靠性优化计划](可靠性优化计划.md) 的 m1c。

## 检查链路

1. 首次启动任务 CLI 前，通过 `git_scope_snapshot` 读取执行前基线并保存到流水线快照。恢复、审批续接和同窗口修复继续使用原基线；不能在改动发生后补建缺失的旧基线。新建的独立任务 worktree 可建立自己的新基线。
2. 编码结束、gate 开始前，重新读取 Git 与磁盘，和基线逐文件比较。即使 CLI 没有上报文件事件、差异为空，也必须完成读取与范围验证 IPC。
3. gate 结束后（包括命令失败）再次读取和验证，纳入测试、构建生成的文件。再在报告保存后、提交或 `DONE` 前复核：文件树若与验收后的证据不同，阻塞任务。
4. worktree 提交 IPC 必须接收已验证快照。原生端在 `git add` 前核对快照，暂存后核对有效磁盘文件树，并读取实际 staged blob 核对内容与文件模式，再核对最终 commit 的 tree 与已接受的暂存 tree、提交后的磁盘文件树。变化则返回错误，不继续合并或清理工作目录。

`scopeBaselines` 和 `scopeChecks` 随 m1a 的持久化屏障保存并在重开时恢复。证据包含仓库根目录、任务目录、HEAD、文件内容指纹、index 条目、变更路径及检查时间。重规划时清除被修改任务的旧证据。

## 变更集合与归属

- 原生读取 `ls-files --stage -z` 和非 ignored 的 untracked 路径；逐文件计算磁盘内容 SHA-256，记录 index blob / mode、删除、符号链接及可执行位。重命名按原路径删除和新路径出现处理，路径中的换行不会被拆开。
- 基线包含已有 dirty 文件的内容。执行前后未变化的用户修改不归给当前任务；同一路径被继续改写时会被识别，不只比较文件名列表。
- CLI 事件只能补充需要检查的路径，不能删减磁盘发现的改动。交付报告和下游 artifact 的文件列表使用实际差异，不采用模型自行生成的列表。任务目录内的绝对事件路径会规范为相对路径；目录外路径阻塞。
- 同一会话的共享目录任务串行派发。不同会话争用同一仓库根目录，或恢复后存在重叠活跃任务且无法证明写入归属时，阻塞；不再用其他任务的 `write_scope` 排除疑似越界路径。
- checkout 的执行占用持续到验证与交付结束；CLI 的结束事件不能提前解除占用。取消 gate 时也要等实际命令返回后才释放占用。

## 失败行为

Git 读取异常或警告、文件读取失败、范围验证 IPC 失败、缺失原基线、目录 / HEAD 改变、范围越界或归属不明，都会保留原因并进入 `BLOCKED`。失败不会进入成功提交、合并或 `DONE`，也不派发依赖该任务的下游。不会自动启动修复轮次；现场留给用户检查。

worktree 缺少任务或 integration 元数据时，同样拒绝以 inplace 成功路径绕过已验证提交。commit hook 若改变了提交内容，错误可能发生在 Git 已创建 commit 之后：该 commit 和现场保留，不作为成功交付继续合并。跨系统事务与崩溃核对仍属于 m1d / m2e。

## 支持范围和限制

- 验证覆盖当前 Git 仓库中的 tracked 文件与 Git 未忽略的 untracked 文件。Git 忽略的依赖、缓存、产物，以及仓库之外且 CLI 未报告的任意写入，不属于这个快照的观测范围；进程写入权限仍由既有 sandbox 负责。本项不是全文件系统审计器。
- 非 Git 目录、尚无 HEAD 的仓库、unmerged / sparse / assume-unchanged index、submodule、无法解析或指向仓库外的符号链接会阻塞，而不是推定验证成功。已有未合并内容的冲突任务也需先满足可验证基线条件，不能以特殊任务名豁免。
- Git clean filter 或换行归一化若改变了已验收的原始内容，提交会阻塞，避免把未经验证的字节当作交付内容。
- 单次扫描上限为 50,000 个文件、512 MiB 实际读取数据；超出即阻塞。快照不写入工作区、不替用户暂存或回滚文件。
- 此检查不是文件系统事务，不能冻结用户或外部进程在最后一次检查之后的任意写入。worktree 提交路径增加了原生端暂存与 commit tree 的复核；完整交付恢复与外部并发协调继续由后续里程碑处理。

## 自动化验收

新增原生 Git 回归 6 项，使用真实临时仓库验证：dirty 基线上继续修改、暂存 / 未暂存 / untracked、删除、重命名及特殊文件名；子目录；只读检查不改变 index；无仓库 / 无 HEAD / submodule / 隐藏 index 标志 / 文件类型异常失败；过期证据拒绝提交；有效删除与新文件提交；权限位、符号链接、Git clean filter 改写已验收内容，以及 commit hook 改写提交树拒绝交付。

新增前端范围检查回归 20 项，覆盖基线 / Git / IPC / HEAD 失败、CLI 漏报、原有 dirty 内容变更、并发归属、成功及失败 gate 的越界写入、gate 后 IPC 失败、报告后文件变化、真实文件列表、绝对路径、缺失 worktree 元数据、人工接管（含 worktree 提交路径）、运行中切换隔离设置、旧会话续接及取消 gate 的占用期限。原有编排测试显式补齐模拟执行的基线；原先允许越界后自动修复的断言改为阻塞。快照新增字段还通过 Rust 持久化往返断言验证。
