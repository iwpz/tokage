# m1d：Git 故障分类与合并一致性实施记录

实施日期：2026-10-16。范围对应[可靠性优化计划](可靠性优化计划.md)的 m1d，承接 m1a 的持久化屏障和 m1c 的验收快照。

## Git 失败如何处理

- Git 非零退出保留命令、退出状态、stderr 和 stdout；超时保留命令及期限，启动失败保留系统错误。
- 合并前确认当前分支与 integration 元数据一致，工作区没有未提交文件或未结束的 merge，并将源分支解析为 commit。正式 IPC 还要求它等于交付记录中的已验收 commit；后续合并使用这个固定 commit。
- 合并失败后使用 NUL 分隔的实际 unmerged 文件列表检查内容冲突，同时确认 `MERGE_HEAD` 指向本次源 commit。只有两项都成立，才中止本次冲突合并并生成集成任务。中止失败、检查失败、HEAD 变化也会阻塞。真实冲突的原始 Git 诊断随 outcome 保存在交付记录；普通错误也完整写入持久化任务日志。
- 缺失分支、锁文件、权限、hook 拒绝、超时等普通故障返回错误并阻塞当前任务，不生成模型修复任务。没有确认内容冲突的未完成 merge 会保留，供检查；不会随意 abort 或强制清理。
- 对已合入的 commit，用 Git 祖先关系对账，复用已有结果，不创建重复 merge commit。读取祖先关系失败仍是错误。

## 提交、合并与清理的恢复协议

`PipelineState.gitDeliveries[taskId]` 随流水线原子保存，含原任务 worktree、integration 身份、验收快照、源 commit 和阶段。旧文件缺少字段时默认为空；重定义任务的 replan 清除对应记录，不把旧交付套到新需求。

1. **committing**：在第一次暂存或提交之前保存意图与完整验收快照。失败时不执行 Git 写入。
2. **committed**：提交后读取 commit 并持久化，再允许合并。若进程在提交完成而记录更新前退出，恢复时核对原始父 commit、提交信息、干净状态、验收文件内容及 index blob / mode，精确匹配才复用。暂存之后退出也可恢复，异常暂存内容不能被悄悄覆盖。
3. **merged**：合并成功或祖先关系确认已合入后，先落盘合并结果，再允许删除任务 checkout。清理不使用 force，保留任务分支；遇到 dirty 或清理失败保留目录和日志，已确认的交付仍有效。
4. **conflict**：持久化真实冲突及集成任务定义、固定准备名称，随后保存冲突 worktree 身份，再预合并。只有准备成功、任务元数据与下游依赖改写落盘后，原任务才可完成；准备失败原任务阻塞，原 checkout 和分支保留。
5. **DONE**：成功路径完成后保存任务状态。若退出发生在合并后、清理前，或目录已清理而 DONE 尚未落盘，恢复使用交付记录和保留的分支对账，不依赖旧目录仍存在。

重启后仍沿用“中断后由用户继续”的交互。存在 Git 交付意图的“继续”、看板“重试”和人工接管完成入口，都先执行 Git 对账，不启动新的模型轮次或重复运行已接受的 gate。源分支变化、integration 缺失、worktree 身份不符时阻塞，不回落到项目目录执行。

任务和集成 worktree 创建也不再吞掉 HEAD 读取错误；集成工作区从已解析的 commit 创建，缺少集成分支不能回退到项目 HEAD。创建后已取得的任务 checkout 身份会先保存，以保留后续 Git 读取失败时的现场。

## 有效的冲突修复工作区

m1c 不允许带 unmerged index 的目录作为执行基线。为让真实集成任务满足这一条件，预合并会在专用冲突分支上创建一个**私有冲突标记基线 commit**，保留两条父分支的祖先关系；集成任务继承原任务的模型及参数，避免生成无法派发的空模型任务；随后模型从干净、可快照的基线开始，仅修改声明的冲突文件。

这个内部基线允许暂存有意保留的冲突标记，因此只在该内部提交上使用临时空 hooks 目录并关闭签名；普通任务提交和正式集成合并仍执行仓库 hooks，并传播拒绝结果。内部提交同样复核原始文件内容、index blob / mode、删除、最终 tree 及磁盘状态，不能借 clean filter 改写未经验证的内容。

准备时再次固定源 commit、核对真实冲突路径。集成分支推进导致出现声明范围之外的新冲突时阻塞并保留现场。最终合并集成任务之前检查冲突文件的常见标记，未解决的私有基线不能直接成为成功交付。准备重试复用已经保存的 resolver checkout，不反复创建任务、重置任务状态或强制删除原产物。

## 验收与保证边界

新增前端回归 18 项，覆盖持久化屏障次序；从实际保存的 committing / committed / merged / 已清理快照冷加载并继续；锁、权限、hook、超时、缺失分支的阻塞；准备失败后恢复同一个冲突工作区；源 commit 或元数据改变；看板重试；dirty 清理失败；提交后、合并后落盘失败时禁止清理。恢复断言不启动模型或 gate。

新增 Rust 回归 8 项，使用真实临时仓库验证 merge 结果重放不增加 commit；缺失分支、index.lock、错误分支、源 commit 不符、dirty 和 hook 拒绝；真实冲突、中止、干净 resolver 基线、准备重放、范围变化、拒绝未解决标记及最终成功合并；暂存后和提交后恢复；私有基线删除与 hooks 边界；Git 退出输出及超时原因。持久化往返测试同步覆盖交付字段。

本项恢复协议针对已保存意图的任务提交 / 合入会话集成分支流程。Git 中途仍有未结束 merge、磁盘损坏、源分支被外部修改等不确定状态，会阻塞并保留产物，不保证自动修复。创建 checkout 成功但 IPC 身份响应尚未返回的窗口，仍可能留下需要人工识别的孤立目录；不会猜测并删除。跨进程资源所有权、任意 CLI 副作用和完整崩溃幂等继续属于 m2e。

此流程不是冻结外部写入的文件系统事务。m1c 的 Git 文件观测范围与扫描上限保持适用。冲突文件内本来就存在独立标记行时，保守的标记检查可能阻塞，需要人工核对。真实冲突保留的原分支与 checkout 会增加磁盘占用，由后续明确的 worktree / 计划清理入口处理。
