# m1e：回滚保留用户原有工作

实施日期：2026-10-16。对应《可靠性优化计划》m1e；完成范围为代码与本机自动化验收。

## 执行前备份与执行后证据

流水线的四个 CLI 启动入口在范围基线检查后、启动前完成内容备份，备份失败即停止启动。原生执行层在启动时再次检查原始备份；全自动模式同样必须先完成备份，不再只记录 HEAD/状态列表或忽略保存失败。

备份按具体 `turnId` 保存于该 checkout 的 `git rev-parse --absolute-git-dir` 返回目录下的 `tokage-rollback/<turnId 的 SHA-256>/`。普通仓库与 linked worktree 分别使用自己的 Git 目录，不向项目的 `.tokage/` 写入回滚文件，也不进入模型的正常文件范围。Unix 备份根目录权限为 `0700`，临时备份目录为私有目录。

`before.json` 保存仓库/执行目录/HEAD、文件指纹、暂存条目、原始 index 字节及普通文件权限。文件名哈希对应未经文本解码的原始工作区字节，`object-<oid>` 对应原始暂存 blob：用户原有暂存与未暂存内容不同、未跟踪文件、二进制、删除及链接均可区分。暂存对象通过单个 `git cat-file --batch` 流式备份、去重并限制体积；恢复时重新写入并核对对象 ID，不依赖未提交 blob 恰好尚未被 Git GC 清理。

字节备份逐项核对内容 SHA-256，前后复读范围、权限和 index，原子发布且不允许覆盖原始轮次备份。沿用 m1c 的 Git 范围边界：最多 50,000 项、工作区读取最多 512 MiB；额外暂存对象备份最多 512 MiB、单次对象备份超时 60 秒。Git 不可读、未合并/sparse/assume-unchanged/submodule 等无法完整校验的状态拒绝启动。`git add -N` 的 intent-to-add 元数据无法由当前逐路径恢复协议完整保留，明确拒绝启动，不声称已保护。

真实 CLI 退出后，成功、失败、协作取消共用结束取证路径，分别持久化 `after-modes.json`、`after.json`；失败不会在点击还原时补拍一个新状态冒充执行结束证据。提供商提前输出的 `Done` 暂存到进程退出及取证之后，再交给前端，避免验收提前修改结束证据。进程非正常结束时不补发已缓存的成功 `Done`。

## 还原协议

1. 用户选择“还原越界文件”，或在停止的失败/取消任务上选择“还原本轮改动”，先确认具体文件列表；后者从原生结束证据读取实际变化，包含暂存变化，不信任模型的文件事件列表。
2. 前端持有同一 checkout 的范围所有权，阻止流水线在还原确认及执行期间再启动写入。运行、验收、修复中的任务，以及已经记录 Git 交付意图的任务禁止从此入口还原。
3. 原生核对备份身份、执行目录、HEAD、明确选中的路径及其结束时内容/暂存状态/权限。任意选中路径发生后续人工改动，整次操作在修改前拒绝；不安全路径、项目元数据路径、原始内容损坏、缺少结束证据、Git 锁失败也不执行覆盖。
4. 在 Git `index.lock` 协议下复制当前 index 到私有临时 index，只更新选中的条目。其他文件的暂存状态保持当前值；选中文件恢复本轮开始时的暂存 blob 或未跟踪状态，不使用 `checkout HEAD`、`reset --hard` 或 `git clean`。
5. 覆盖或删除前，在原始备份下建立持久 `recovery-*` 目录，保存当前字节、文件状态、权限、原始当前 index 及当前暂存 blob。副本完成并复核后才开始改写。每个文件落地前再次检查现场；普通文件以临时文件替换并同步，最后原子替换 index 并复查选中路径。
6. 任一步失败都返回失败；若已经改写部分文件，错误包含已还原路径和 `recovery-*` 路径。前端保留失败/越界证据，任务不会被改成成功。不会将部分成功显示成全部成功，也不自动重复有冲突的还原。

成功信息包含可恢复副本的实际绝对路径。`state.json` 与 `modes.json` 给出路径、指纹、链接目标和权限；普通文件副本采用相同的路径 SHA-256 命名，`index` 与 `object-*` 保留撤销还原所需的暂存内容。出现部分失败或跨轮次冲突时，保留这些副本供人工核对，不自动猜测覆盖。

失败证据增加明确 `turnId` 并随 pipeline 原子保存/恢复。越界还原使用该证据所属轮次；整轮还原使用最新轮次。取消后续修复并还原最新轮次，不会清除上一轮仍未解决的越界证据。旧版没有内容备份或轮次身份的记录明确拒绝自动还原。

## 界面与恢复边界

默认仍为每任务独立 worktree；本节点没有改变默认隔离策略。设置说明明确：`inplace` 会直接修改项目目录，自动备份只覆盖 Git 已跟踪与未忽略文件，后续人工改动或证据不足时需要人工恢复。确认文案不再称“恢复到 HEAD/直接删除”。失败与取消入口不会自动回滚用户工作，必须由用户选择文件并确认。

这不是任意文件系统事务：忽略文件、仓库外写入、数据库/网络/其他外部副作用不在备份范围；外部程序在执行期间的写入无法区分为代理或人工修改。选中路径存在取证后修改时保守拒绝，即使两次修改在文本上可以合并也不自动合并。文件 ACL、扩展属性、所有者及目录元数据不在本节点的还原保证中；Unix 普通文件权限和链接目标包含在校验中。

同一前端进程通过现有范围所有权串行化；其他应用/其他 Tokage 进程不受这一内存锁约束。Git 锁可阻止正常并发暂存；普通文件的校验与替换之间仍有无法完全消除的外部写入窗口。全面跨进程资源所有权与崩溃幂等属于 m2e。

进程被强制中断、取消超时触发任务 abort、结束取证失败、HEAD 已变、备份损坏、或部分还原后再次请求，会保守阻止自动还原并保留可用现场。真实 CLI 的结束路径已覆盖；Debug Mock 绕过真实 CLI、没有相应结束证据时，同样拒绝自动还原。已提交/合并的交付不通过本入口撤销。

备份不自动按时间清理，避免提前删除唯一副本；任务 worktree 正常清理时相应 Git 管理目录随 Git 清理，`inplace` 的备份保留在原 checkout Git 目录内。批量还原会反复验证工作区，大仓库可能耗时较长；没有把这种成本换成静默降级或跳过校验。

## 自动化验收

- 原生真实 Git 仓库：已有暂存与未暂存字节不同、已有未跟踪文件、代理新文件、二进制、删除/重命名、暂存原始 blob 被删除后从备份重建、无关后续暂存保留。
- 保护性拒绝：后续人工文件修改、后续暂存变化、权限变化、缺失/未封口/损坏备份、重复轮次、index.lock、错误仓库/HEAD、不安全路径、越界链接、intent-to-add。
- Unix 权限故障：前一文件已还原、后一文件无法删除时返回部分失败，明确列出已改写文件和可恢复副本；正常非 root 用户运行此权限故障分支。
- linked worktree 与项目子目录的备份、路径与恢复正确；备份不会污染范围扫描。
- 使用本地脚本替身走真实适配器与子进程，覆盖成功、失败、取消后封口和 `Done` 延后；不调用付费模型服务。
- 前端：失败/取消/越界三个入口、用户放弃、原生部分失败不清证据、启动前备份失败、活动任务与交付意图禁用、还原期间派发互斥、确认期间轮次变化、跨轮次证据保留及冷加载后身份恢复。

最终验证：

- `npm test`：34 个文件，235 项通过。
- `npm run build`：通过（保留已有的打包体积与混合静态/动态导入提示）。
- `npm run check:i18n`：1604 个键，110 个 TS 和 126 个 Rust 文件检查通过。
- `cargo test --workspace --locked`：553 项通过、26 项原有忽略、0 项失败，23 组测试结果；新增 9 项原生回归。
- 前端新增 8 项回归，包含失败证据的冷加载身份验证；Rust pipeline v2 roundtrip 另复核失败轮次字段的落盘还原。
- `git diff --check`：通过。

本节点未执行付费真实模型需求，也未进行桌面界面人工端到端操作；按钮行为由前端逻辑测试、原生协议及真实本地 Git/子进程测试共同验证。
