# m2b：自然语言需求到最终交付

## 验收范围

沿用 m2a：macOS arm64，Claude Code 2.1.296 / `haiku` 官方订阅，以及 OpenCode 2.0.29 / `deepseek/deepseek-flash` 官方 API。本轮使用独立临时仓库、会话 worktree、任务 worktree 和会话 Full Auto，真实调用会消耗对应账户额度。

新增 `scripts/run-m2b-desktop.sh`，默认依次运行这两个组合。只运行其中之一可传 `CLAUDE_CODE` 或 `OPENCODE`。脚本构建显式开启的验收包，运行完恢复普通前端；任何构建或组合失败均返回非零。历史 `scripts/run-live-desktop.sh` 仍是预制计划回归，不作为本节点的自然语言证据。

## 场景与独立验收

已有 Node ES module 仓库包含价格计算、金额格式化和发票集成三个缺陷模块。通过渲染后的聊天输入框提交自然语言需求，由实际 CLI 自动规划；生产解析器和桌面计划审阅界面处理模型回复。验收入口只检查生成计划，不写入或修补任务图。计划必须包含独立并行任务、后续集成、公共契约和独立测试命令；不满足时失败。

运行前执行 `npm ci --ignore-scripts --no-audit --no-fund`，记录环境准备结果。本场景无第三方依赖，不证明外部包下载、认证或复杂构建环境可用。

独立检查器由 `scripts/live_natural_fixture.py` 提供，执行模型不能决定预期结果。检查空输入、零值、整数计算、非法价格/数量、正负金额格式，以及集成输出与错误传播。先确认初始三个模块的预置缺陷均触发失败；本地 mutation 回归另外覆盖算术、负数格式、删去边界校验、硬编码集成及修改测试为直接成功。

交付前，桌面等待独立 Python 进程检查集成分支：所有原始测试/包文件保持原文、实际并发有时间重叠、集成在两个上游结束后启动、完整门禁成功，并使用独立保存的原始 oracle 验证实际模块。只有外部检查通过且检查提交与应用验收提交一致，才点击合入。合入后再次运行独立检查、检查 Git diff/任务提交/干净状态/数据库归因。最终交付目标是会话 worktree 分支，原始 fixture 主分支保留。

这是渲染后 DOM 事件驱动的桌面实机自动验收，覆盖真实 Tauri IPC、CLI、文件、门禁和 Git，不代表人工鼠标操作、视觉布局或辅助功能体验验收。人工代码审阅需核对原始需求、生成计划、公共契约、实际改动与遗漏；不可仅依赖模型 TaskReport 自述。

## 本轮发现与修复

- Claude Code 官方订阅第一次真正请求返回 OAuth token revoked；检测显示 READY 不能证明后续请求认证有效。本机重新登录后继续复验，没有切换认证渠道或模型。
- OpenCode 首次自然语言规划返回了完整需求/公共契约/并行 DAG，但任务 `goal` 中的未转义 `Total: ` 导致 YAML 解析失败，桌面没有可审阅计划。已归档该真实回复为 `src-tauri/crates/tokage-planning/tests/fixtures/m2b-opencode-plan.md`。
- 解析器现在先对 `title` / `goal` 中这类未转义的冒号做局部文本转义，再尝试完整类型反序列化；只有仍失败才进入原有字段容错。回归必须核对三个任务、四个契约、准确依赖、文件作用域、原验收命令。没有将计划换成预制图，也没有改动验收命令来获得通过。
- 规划提示补充 YAML 引号要求；无法解析时，空计划界面展示解析错误，避免仅显示“没有计划”。

第二次 OpenCode 已完成真实并行执行、后续集成和外部独立检查，但最终合入被正确拒绝：`save_plan` 自动写入的未跟踪 `AGENTS.md` / `CLAUDE.md` 使会话检出变脏。修复后，Git 文件形式的检出（包括 linked worktree 及其项目子目录）仅更新 `.tokage/` 上下文，保留原有指引文件，不新增或重写根指引；提示中的明确路径继续向 CLI 传递上下文。原有主检出初始化行为不变，不把首次主检出初始化产生的文件视作已自动交付。回归使用真实 Git worktree 验证干净状态、用户指引原文和子目录场景；没有放宽干净检出门禁、忽略指引文件或删除现场文件。

重新登录曾将默认 Claude CLI 自动更新到 2.1.301，该尝试被精确版本检查拒绝。验收脚本支持 `TOKAGE_CLAUDE_TEST_BIN` / `TOKAGE_OPENCODE_TEST_BIN` 指定已有可执行文件，本轮使用本机保留的 Claude 2.1.296，不重写用户默认路径或安装版本。

后台停滞另有实机记录：Claude 子进程已退出，但前端停留于规划，五分钟超时也未推进，最终停止该次验收并保留现场，不能算完成。当前 Tauri 默认后台策略可能在隐藏约五分钟后挂起视图；生产 `tauri.conf.json` 现设置 `backgroundThrottling: disabled`。macOS 14+ 支持该设置，本轮只对 macOS 27.0 / build 26A428 / arm64 作实机结论，不推及不支持该设置的平台。Claude 脚本默认先隐藏窗口 310 秒，再恢复并执行自然语言需求；Python 独立观察时限，后台探测超过目标时长 20 秒仍未回传须失败，不将用户重新激活后迟到的计时当作后台成功。此探测不消耗模型额度。

旧构建中的一轮 Claude 运行已在确认存在上下文文件导致的交付阻塞后主动停止，不继续消耗额度去等待已知会失败的交付；记录为取消，不计为通过。所有首次失败、配置版本拒绝和主动取消均见 [尝试记录](reliability-evidence/m2b/failures.json)。

## 人工审阅与限制

- 对照原始需求检查：三个模块分别负责验证/求和、金额格式化和组合；集成必须真实导入两个上游函数，不能复制逻辑或硬编码样例结果。价格与数量的空输入、零值、负值、非整数，以及错误向发票模块传播均有独立依据；原测试、断言、包脚本与锁文件不允许改变。
- 金额样例按整数分验收。原始请求没有定义 `money` 的分数分/非数值输入应舍入还是报错；Claude 计划明确新增“非整数分抛 RangeError”的假设，OpenCode 未承诺相同行为。审阅接受本例的整分输入域，不将两个实现的全部输入行为视为等价，也不将该额外假设当成用户原本要求。实际业务需求应先明确这一点；超大整数精度同样不在本例结论内。
- 真实 DOM 事件、原生调用和真实 CLI 可以证明限定流程经过，不证明人工点击体验、窗口视觉布局、外部包下载、所有输入或长时间生产使用。没有第二个模型自述充当独立验收；判断依据是外部检查器与人工源码核对。
- 分配器中的成功率预测、替代模型估价与 UI 首次通过指标不作为本节点的质量/成本证明；对应口径仍属于 m3。历史一次额度事件替身测试空事件失败仍如实记录，单独复跑与最终全量通过，未确认其根因。

额外人工边界检查见 [OpenCode](reliability-evidence/m2b/opencode-manual-review.json) 与 [Claude](reliability-evidence/m2b/claude-manual-review.json)。Claude 原始结构化累计用量较大，已保留原值但尚未校准累计/重复事件口径，不解释为账单金额或节省证明；该项仍需 m3b 核对。
