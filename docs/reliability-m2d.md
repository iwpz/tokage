# m2d：进程、网络、额度与审批故障

验收日期：2026-10-19。本轮范围：macOS 本机的分层故障注入，覆盖生产前端编排、原生 CLI 监督、真实操作系统进程树、真实 Git / hook 和 SQLite 费用读取。CLI 网络、认证及额度错误使用合成协议输出，未消耗模型额度，也未修改本机网络或账号余额。真实桌面和选定服务商的关键异常路径仍须在 m2g 归档，不能以本记录替代。

## 修复

- 取消先撤销任务的事件所有权，再等待停止确认。停止期间的迟到成功、错误及审批事件不能复活任务、执行 gate 或推进下游。准备 CLI 时再次核对当前 turn、任务和队列；取消不会被启动失败的异步回调改回 BLOCKED。
- 暂停队列停止新派发，已运行任务可以完成；“中断执行”停止当前 CLI / gate，保留会话和 worktree 供显式继续；取消使任务进入终态并跳过尚未启动的下游。停止确认前保留共享检出的写入所有权；停止 IPC 失败时保留可见日志、中断队列并保留锁定，需检查停止进程并重启 Tokage 核对遗留进程后再继续。中断多个任务会等待所有停止请求返回，再汇总失败。
- gate 在等待全局串行队列前就登记取消入口，重复 run ID 拒绝覆盖原拥有者。取消 IPC 等待实际退出和管道回收；父命令已退出、后台子进程仍占用输出管道时，也会回收进程组。管道读取有明确截止时间，不能无限挂起或默认为通过。
- CLI 的 stdin 写入、stdout 读取及 stdout 关闭后的进程退出等待均接受取消和硬超时；审批期间只暂停空闲计时，硬超时继续。CLI 提前关闭 stdin 时继续收集退出协议和 stderr，保留认证 / 额度错误；不能用 BrokenPipe 掩盖服务端错误，也不能把未送达输入的成功帧放行为成功。提前退出时中止独立 stderr 读取任务；最终文件证据、回滚封存期间收到取消，也不再发送成功。
- Git 读写共用受监督的进程组并登记启动清理记录；超时回收 hook 和后代。信号导致的异常退出不能误当成 diff 的正常退出码 1。集成提交 / 合并之间及等待合并锁之后重新核对任务所有权。
- 集成期间取消不承诺撤销已经发出的 Git 操作：操作可能完成，其 committed / merged 事实继续落盘，但取消后的任务不能被标为 DONE、自动清理 worktree 或启动下游。现场保留，供人工核对事务、分支和提交；崩溃恢复与重放的完整验收属于 m2e。
- 审批按审批 ID 串行处理。拒绝使任务阻塞、停止当前 turn，撤销同命令的任务授权，不通过“换个方法继续”的自动重启形成拒绝循环。未解决审批随任务持久化；恢复后不会自行增加授权或启动模型。
- Claude 的任务会话授权改为完整命令匹配，不再追加 `:*`；含通配符或无法安全编码的命令不转换成授权。依据：[Claude 官方权限规则](https://code.claude.com/docs/en/permissions)。这里授权的是该任务后续 CLI turn 使用同一完整命令，不是任意参数前缀。
- 当前 headless 通道不能证明“仅执行一次”或统一的项目权限范围，因此这两类选择不扩大授权、不自动恢复：一次授权记录决定后提示人工接手，项目授权保留待处理并提示限制。其他 CLI 的命令审批恢复同样不映射成更宽的 workspace 权限；可使用终端接手并重新验收。Claude 精确命令的会话授权可以恢复。
- 每次新建、继续、修复及审批恢复 CLI 前读取预算。已记录费用与在途任务估算共同约束新派发；预算读取失败、未知费用、缺少在途估算或超出预算时暂停队列。SQLite 汇总保留 unknownCostEvents，缺失价格不能当成已知免费。

## 故障场景和证据对应

- 任务执行：`chat/baseline_failures.rs` 使用 Claude / OpenCode 真实解析器及 run_cli，注入连接中断、429、402、认证撤销、CLI SIGKILL，验证失败归类并且没有 Done；另覆盖 stdin 阻塞、stdout 提前关闭、持续输出仍触发硬超时。
- 审批等待：原生 FakeAdapter 走生产监督，验证硬超时不因待审批而失效；前端回归覆盖拒绝不重试、重复点击仅创建一次决定和一次恢复、未知范围不扩权、落盘后恢复仍待审批。Claude 参数回归验证精确命令且拒绝模式注入。
- 应用强杀：`proc::tests::m2d_sigkill_host_reaps_registered_tree` 启动单独的原生测试宿主，真实 SIGKILL 后确认其子孙仍活着，再通过生产 cleanup_leftovers 回收，重复清理无残留。它验证原生宿主的进程注册与启动清理机制，不等同于强杀完整桌面应用并恢复业务状态。
- gate：`gate_m2d_tests.rs` 覆盖排队取消、重复 ID、父进程先退出、忽略 TERM 的进程树以及停止确认；既有 F5 测试覆盖超时和孙进程回收。`acceptance.test.ts` 验证错误、异常、取消及迟到成功都不能放行交付。
- 集成：`git/m2d_tests.rs` 运行真实 pre-commit hook 超时和信号退出，核验后代消失且用户暂存内容保留；`gitDelivery.test.ts` 在提交 / 合并尚未返回时取消，核验保留 committed / merged 记录及 worktree、不启动下游。既有用例验证 index.lock、权限、hook 拒绝、超时、缺失分支不能冒充冲突或成功。
- 修复与接手：既有 F13 梯级回归覆盖同窗口修复、改派及最终 BLOCKED，保留失败证据；F10 接手路径重新执行 gate 后才能 DONE。取消后正在等待的修复决策失去所有权，不再发起修复。预算检查也覆盖修复 turn；供应商健康读取失败会明确阻塞修复并保留原 gate 证据。
- 预算：前端注入费用数据库不可读、未知费用、已记录加在途估算超限和硬上限；原生 SQLite 用例验证实际价格、等价价格、未知价格及读取失败。暂停不主动杀掉已经运行的模型，也不把估算当作服务商账单的实时硬额度。

## 验证

最终命令、结果和原始日志见 [validation.md](reliability-evidence/m2d/validation.md)。重点用例可无模型账号复跑：

```sh
npx vitest run src/lib/taskRunner.test.ts src/lib/gitDelivery.test.ts src/lib/acceptance.test.ts
cargo test --manifest-path src-tauri/Cargo.toml --workspace --locked m2d -- --nocapture
```

原生宿主 helper 标记为 ignored，专供父测试作为独立子进程调用；父测试会校验其启动、强杀和进程清理，不以该 helper 的单独 ignored 状态充当通过。

## 尚未证明的边界

- 没有把协议替身故障说成服务商真实断网、账号实际额度耗尽或完整桌面强杀恢复；后者的实机矩阵和证据仍留 m2g，恢复最终代码一致性留 m2e。
- 进程组回收覆盖未主动脱离组的后代，不承诺追踪主动 setsid / 脱离 Job 的恶意进程。启动清理依赖正常落盘的进程登记；PID 重用、登记损坏及多应用实例竞争未在本轮认证。
- 已发出的 Git 操作按其原生命令超时收敛，取消不强制回滚已发生的提交或合并；不能将 UI 取消解释为 Git 从未改变。强杀产生的 index.lock 等仍需核对进程、提交和事务后人工处理。
- 预算是停止新派发的约束。在途实际费用可能超过估算、服务商用量可能迟到，已运行 turn 仍可能超支；不承诺资金绝对不超过该数值。费用定价校准另属 m3。
- 持久化多文件原子性、跨进程幂等性和完整业务恢复仍留 m2e；IPC 五个既有无生产调用缺口仍留 m2f；通过本机回归不代表整个 M2 或日常可靠性已经完成。
