## m3a-001：会话页阅读位置与最新输出

现状依据：`SessionHistoryView.tsx` 的右侧仅为 overflow 容器，没有跟随最新输出或返回最新位置的机制。已修复的消息更新能进入 DOM，但较长会话的最新活动可能在视口之外。

目标：当用户处于底部时跟随新增输出；用户向上阅读时保留位置，并提供返回最新内容的入口。切换 attempt 后不能沿用上个会话的滚动意图。

范围：会话消息视图、必要的滚动状态辅助逻辑、中英文文案及有意义的回归。派发前允许为可控 DOM 测试增加最小开发依赖及对应锁文件；不变更运行时依赖。非目标：主聊天交互重构、数据库结构、自动授权与模型路由。

派发前固定的验收：

- 初次进入选定 attempt 能定位到最新内容；新输出在底部阅读时可见。
- 向上滚动后，新消息 / 工具过程不抢走阅读位置；返回最新入口可用键盘操作。
- 切换 attempt、空记录、加载失败和流式结束不会误用旧滚动状态。
- 可控 DOM / 滚动容器回归覆盖上述状态，TypeScript、全量前端测试、国际化检查与生产构建通过。
- 实际桌面运行中确认真实 Luna 事件产生新内容时的行为，保留 session / attempt、DOM 检查与交付提交。纯辅助函数测试不能代替这一步。

三次业务派发均使用 GPT6 Luna。第一轮未确认离线依赖安装门禁；第二轮命令门禁通过但没有交付 DOM 回归，独立审查拒绝合并；第三轮具备 6 个真实 React / happy-dom 回归，但曾修改并撤销越界的 `vite.config.ts`，范围检查仍正确阻断。

此后由外部 Codex 审查者人工接手，只采纳原范围内六个文件，并在主仓库独立执行全部前端检查。候选提交 `3ced8cf951c19c27f6327a0031e6cb5f85818953` 用于构建后的真实 Luna 只读滚动验证；它不是 Tokage 自主流水线成功交付的证据。最终交付提交、耗时和验收结论记入台账。
