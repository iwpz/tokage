# 高层编排共享服务迁移计划

日期：2026-10-21。状态：sh1、sh2a 已完成，sh2b–sh2e 及 sh3–sh4 未完成。独立于可靠性 20 项真实需求验收，10/20 保持暂停。完成本规划不代表 App / CLI 已共享完整编排，也不代表真实模型验收通过。

## 目标与完成定义

让 App 与 CLI 通过同一 Rust 应用服务处理需求、规划、模型分配、授权、任务执行、审查和交付。入口只负责输入、展示、交互和传输，不再决定任务是否完成、能否重试、门禁是否通过或允许合并。

“共用代码”不要求相同运行数据目录、相同 UI 或强制相同策略。相同服务版本、需求、有效配置、授权及外部结果，应产生相同的业务决策和持久化证据。串行 / 并行、自动修复 / 人工介入等差异必须是服务理解并记录的正式配置，不能由入口各写一套流程。

完成迁移须同时满足：

- App 和 CLI 均调用共享服务；两端原有编排中的状态转换、调度、授权、门禁、重试和交付决策已删除或转为服务调用。
- 同一运行只有一个权威状态及执行 owner；视图断开不丢任务，客户端不能以覆盖快照方式制造 DONE / DELIVERED。
- 保留 App 原有能力，CLI 对不能交互或尚未支持的能力明确报告等待 / 不支持，不静默降级或放宽授权。
- 两端契约回归、故障恢复回归和隔离检查通过；真实 CLI 链路和桌面正常 UI 分别验收，结论分开记录。

## 已确认的现状

App 的 `src/lib/taskRunner.ts` 承担任务派发、审批、并发、预算、Provider 熔断、修复、任务接受、集成、最终门禁和交付。相关状态和流程还分布于 `src/stores/execution.ts`、规划界面及调度调用方，不能仅搬走一个文件就宣称迁移完成。

CLI 的 `cli/src/runs.rs`、`execute.rs`、`delivery.rs`、`turn.rs`、`state.rs` 实现独立的高层编排和 JSON 状态，当前是串行、同一指定 Provider/model、显式计划授权、失败保留与显式重试。它不继承桌面设置，不具备 App 的完整修复 / 分配 / 审批能力。

两端已共用 `tokage-core`、`tokage-native`、`tokage-planning`、`tokage-orchestration` 等底层服务。App 依赖 Tauri / SQLite，CLI 是独立 Cargo workspace；共享服务不能反向依赖任何入口。

## 目标边界

新增建议 crate：`src-tauri/crates/tokage-runtime`，提供无 Tauri、无 React、无终端 IO 的应用服务。名称在实施 sh1a 固定后成为契约。

依赖方向：App 的 Tauri 适配层、CLI 命令层 → tokage-runtime → 既有领域和原生服务。SQLite 适配实现可依赖 tokage-storage，不能让 tokage-storage 反向依赖 runtime。若产生循环，仓储 DTO / trait 放 runtime 的独立模块或 core，先评估再拆最小契约 crate，避免提前引入一组空壳包。

复用现有 gate、scope、Git journal、沙箱及 Provider adapter。新增服务负责协调它们，不重新实现它们。`cli/` 可以保留独立 workspace，通过 path 依赖 runtime；两个 lockfile 均须固定和验证。最终是否合并 Cargo workspace 单独决定，不作为本次前置条件。

服务拥有：

- 规范化需求 / 计划 / 有效策略、模型分配及执行身份。
- 状态机、DAG 调度、并发 / 预算控制、熔断、修复与审批生命周期。
- 原生 turn / gate 所有权、流式事件、用量归因、取消收尾。
- 任务接受、范围证据、提交 / 集成 journal、最终审查 / 门禁、精确交付事务。
- 持久化事务、revision fencing、恢复和幂等命令。

入口保留：

- App：界面、焦点 / 滚动 / 搜索 / 折叠、本地化、系统文件对话框和通知。
- CLI：参数解析、stdin / stdout / stderr、输出格式、退出码、信号到取消请求的转换。
- 两端将用户真实确认转换为有范围的服务命令；有效授权由服务核验。界面中的按钮存在或 CLI 的 `--confirm` 本身不构成跳过服务校验的理由。

## 公开契约草案

按类型定义 `CreateRun`、`GeneratePlan`、`ImportPlan`、`ApprovePlan`、`StartExecution`、`ResolveApproval`、`CancelRun`、`RetryTask`、`ResumeRun`、`ReviewDelivery`、`MergeDelivery`、`ExportPatch`、`KeepBranch`。不提供通用 SetState 或任意 SQL / Store 写入接口。

修改命令携带 `commandId`、`runId`、`expectedRevision` 和必要的确认摘要。服务先校验状态 / 权限，再原子保存命令意图，返回 durable revision 或明确冲突；相同 commandId 重试返回同一结果，不能重复发起模型或 Git 副作用。UI/CLI 中收到 RPC 成功不等于业务执行完成。

查询提供运行快照、任务 / attempt / gate / approval / delivery 证据和带游标的事件读取。事件包含 schemaVersion、runId、单调序号、revision、attempt/turn 关联及结构化类型。状态变更和对应事件在同一事务保存；事件投递允许重复，消费者按序号去重。慢消费者从持久事件重放，不能靠无限内存队列保证交付。

原生事件保留 Provider/model 的 requested 与 observed 字段，未知实际模型及费用写 null；规划、执行、审查各自有 attempt 身份。共享服务统一 usage receipt 去重，不把多个事件重复计费。生产事件需脱敏，禁止记录环境秘密。

进程内调用与 Tauri / CLI 传输共用上述契约。本次先不引入网络 daemon、远程 API 或额外监听端口。跨进程接管通过共享仓储和 OS owner lease；CLI 指向 App 正在持有的运行时应返回 owner conflict，不允许两个进程同时推进。

## 状态、配置与授权

采用版本化运行模型和统一持久化仓储接口；首选复用 SQLite 及现有 migration / writer 机制。原 CLI JSON 导入是显式、备份后、幂等迁移，不把旧文件静默识别为新状态；旧记录不能凭空补出审批、用量或接受证据。无法证明已接受的运行保持只读历史或进入待人工对账。

App 历史 DB / PipelineState / 文件 journal 先建立映射和权威来源清单。迁移中一个运行只能选择旧引擎或新服务，选择在派发前固化；不在活动运行中切换，不双写推进。已有活动运行保留旧引擎直至完成或显式安全迁移。未知 schema 不自动执行。

两端配置由入口正常读取并转换成 `EffectiveRunConfig`，在运行中冻结并记录来源 / hash：模型与能力、信任、权限层、并发、预算、超时、修复策略、命令策略、自定义包及协作者设置。CLI 独立配置与 App 用户配置可以不同，但不得依赖隐藏环境补丁。变更影响授权 / 候选时必须重新确认，不能复用旧摘要。

授权须绑定规范化计划、模型分配、工作区 / 范围、目标身份、策略版本与确认命令。服务不信任模型自带 confirmedCommands。FullAuto 仍要求适配器能力、平台和工作树条件。审批响应绑定 approvalId / turnId / revision；重复、过期、已结束窗口的响应不能启动额外 turn。

执行 owner、预算预留及并发槽由服务统一管理。取消应区分 requested / stopping / stopped，收到请求不能直接标记任务已终止；进程清理未知时禁止重派发。恢复先核实 lease、原生进程、启动 receipt、源工作树和 Git journal，不凭持久化 RUNNING 推断成功或失败。

Git 操作采用意图落盘 → 副作用 → 精确结果对账 → 状态确认。任务提交、集成和最终合并都要覆盖响应丢失窗口；复用已有 journal，补齐 CLI 当前“集成后状态保存前中断需人工处理”的缺口。合并始终绑定接受源快照和原目标身份；dirty / stale / 用户正在进行的 Git 操作均拒绝，不自动 push。

每个子节点完成实现、相关回归与进度更新后独立本地提交，提交含标识。不自动 push。以下复选框仅在各节点实际完成后勾选。

- [x] sh1b：建立 runtime crate、命令 / 事件 / 错误 / 有效配置契约与纯状态转换；加入 schema/revision 和命令幂等规则。验收：无 Tauri / 前端 / 终端依赖，旧命令与未知版本的兼容行为明确，禁止任意覆盖状态。

## 验证与实施顺序

顺序为 sh1 → sh2 → sh3 → sh4；sh2 的实现可先以新服务测试覆盖而不接管旧运行。首选 CLI 先接入来验证无头服务契约，再迁移 App 的复杂交互。不能把“CLI 接上共享服务”当 App 已完成迁移。

每节点运行有针对性的领域 / 仓储 / 命令或组件回归；Rust 统一限制两个编译 job / 两个测试线程，前端两个 worker。相关 crate 在桌面 workspace 和独立 CLI workspace 均构建验证；边界变更检查两个 lockfile。前端迁移执行现有完整测试、typecheck、i18n、build，不能删断言来适配迁移。

契约测试覆盖输入拒绝和副作用，而非仅比较私有 helper 返回值；业务 fixture 从测试目录注入依赖，不进入产品入口。原型模型名称崩溃的第十项不混入服务迁移实现，也不计本计划完成数。

## 回退和决策闸门

服务接入以运行创建时明确选择引擎版本，不能通过测试环境变量切换行为。迁移阶段保留旧运行读取 / 收尾能力，不同引擎不能同时拥有一个运行；若需临时产品发布开关，须正式配置、对普通用户有一致语义并单独审查，不能新增验收隐藏开关。

回退仅停止创建新服务运行、保留已创建运行和原证据；发生不可逆 migration 或 Git 副作用后不得用旧二进制盲写新状态。先备份、核实版本，再使用兼容读取 / 显式导出恢复。sh1c 必须给出真实迁移 fixture 和失败恢复结果，才能接入现有数据。

sh1a 固定前需基于代码进一步决定的细节：统一运行与现有 main session / plan / attempt 主键映射、事件存储保留策略、桌面旧运行收尾期限、模型分配 / 修复的默认策略。当前不预估人日或给出完成日期，以节点验收结果推进。
