# T03：可追溯的任务质量与学习口径

日期：2026-11-01（Asia/Tokyo）。本节点完成共享运行的只读质量投影、看板/顶栏/学习输入接线及离线生产入口回归。没有读取个人运行数据或启动真实模型/桌面验收；不增加暂停中的 9/20 连续试用计数。费用、credits 与节省的汇总仍归 T04。

## 问题与选择

T02 发现共享运行的执行证据与旧 task_outcomes/learned_stats 不在同一链路。本次进一步确认：旧看板空样本返回 100%，周期内无样本时回退全部历史；顶栏/界面也默认 100%。旧 runner 将改派后完成写成 FIRST_PASS，旧 outcome 又缺少足以核验的 run/attempt 来源绑定，直接合并会重复或错误学习。

采用**从权威快照只读重算**，不双写旧统计表，不把派生质量反向作为执行成功证据，不通过回填历史制造准确率。质量链路不涉及账单改写或模型主动验证。

## 分类与证据

[`tokage-runtime::quality`](../src-tauri/crates/tokage-runtime/src/quality.rs) 按 run/task 生成稳定 key，返回当前 revision、runState、原执行模型与身份来源、尝试 ID、证据摘要及时间。模型为 CLI 上报或请求配置时分别标注；请求名不冒充实际模型确认。

- FIRST_PASS：只有一次模型尝试，且存在有效 report/scope/gates/清理/commit/integration 接受证据。Done frame、文本“成功”和最终审查通过本身都不替代任务接受。
- FIXED_IN_WINDOW：多次模型尝试、同模型配置与同一个已知原生 thread，最终被接受。
- REASSIGNED / RETRIED：变更执行模型配置后接受，或同配置但换窗/未知窗的重试后接受；均不成为原任务首次成功。
- USER_TAKEOVER：有效人工 receipt 经过相同门禁接受；不会伪造模型完成轮次。
- BLOCKED / IN_PROGRESS：当前未定案，不作为完成样本或成功学习。
- ABANDONED：已停止且原生清理确认、任务未接受。用户取消不自动当成模型失败；仅有确切原生失败记录时才可作为失败学习输入。
- REMOVED：增量计划撤回的未接受任务，保留其原生尝试；原任务元数据/撤回时间不足时不训练。
- UNKNOWN：接受证据缺失/不一致、清理未确认、审批续接无法确认是否首次通过等情况；不补成功，也不拿未知当失败训练。

人工接受和所有模型接受都保留共享运行的 runState；例如 AwaitingMerge 说明任务已接受而运行尚未交付。**任务首次通过率不等于运行交付率，也不是纯模型能力基准。**

同一任务的旧尝试不会因 Retry/PrepareRetry、改派或重新审批变成新的首次样本。计划先撤回再用相同 ID 加回时，还会结合仍保留的原生 turns：不能以丢失 task.attempts 链重新算 FIRST_PASS，元数据不完整的部分禁用学习。

## 时间与数据目录

新接受证据新增兼容的可选 acceptedAt，在服务确认集成并接受任务时写入。历史未带该字段的记录不按旧模型完成时间伪造接受时间；停止/撤回没有确切终态时间时同样保持未知。

周期比例沿现有看板采用 UTC 日界/滚动 7 或 30 天，不回退全部历史。缺日期的已定案记录可在证据区查到，并明确排除于周期比例；没有核验样本返回 null，界面显示“—”。未定案状态可展示，排除分母。

App 仅读取显式 App data root 的 runtime-v1；CLI 在自己的所选 data root 中冻结其本地学习输入。没有隐式扫描别的 CLI/App 目录、复制账号或合并不同命名空间同名运行。只读 Reader 不创建 owner、不迁移数据库；损坏/未知库报错，不能变成空样本或继续展示旧周期成功率。

## 学习与历史数据

每个已定案逻辑任务最多贡献一份首次通过观察，归原执行模型；FIRST_PASS 为 alpha+1，其他可核验非首次结果为 beta+1。改派获胜者与人工工作不追加“新的首次成功”。源为请求配置时会保留 REQUESTED 标签，不能据此证明厂商实际服务了该模型。

按稳定 key/revision 重算并选取最新投影，不追加计数；重读和重复通知不会重复学习，临时阻塞不会提前写成永久失败。knowledge-pack 先验与观察权重分开，观察从 0 开始；预测仍是后验估计，不是质量保证。

接线范围：App runtime_config、旧匹配/改派 IPC 的质量 LearnedIndex、设置页 list_learned_stats、CLI 新运行的冻结 PlanningPolicy。既有运行的冻结策略不被修改。模型级 `*` 汇总与 provider 行不会在设置页 n 中相加两次。

旧 task_outcomes/learned_stats **保留在磁盘、不删除、不追认**；缺少来源关联的旧质量 alpha/beta/fix-rate 不进入当前核验学习，看板单列未核验数量。旧成本校准/用量 profile 仍保留其原路径，是否可比较由 T04 继续核对。旧 runner 后续改派完成已改记 REASSIGNED，但单凭这个字符串仍不足以追认旧数据。

这意味着升级后原先依赖无法核验旧计数的预测会回到知识包先验，再结合可核验共享运行的本地观察。历史共享任务即使日期未知，只要接受与身份来源可核查，仍可参与全部历史的学习；周期看板与全部历史学习不是同一个分母。

## 界面

- 看板与顶栏不再将空样本、旧 backend 缺少来源字段、读取失败或迟到的旧周期响应显示为 100%。
- 质量卡显示核验样本数、旧未核验数和缺日期数。证据区展示 outcome、run ID/revision、runState、模型来源、attempt IDs 和证据摘要，缺日期显式标注。
- 知识包页区分知识包先验与已核验本地首次通过样本，预测提示明确不是实测保证。
- 没有把模拟浏览器数据、离线协议 fixture 或当前单测写入真实质量账本。
