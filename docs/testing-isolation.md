# 测试隔离与真实需求验收规则

生效日期：2026-10-21。从 m3a-010 起执行；适用于后续所有真实模型、桌面及发布验收。历史 1–9/20 使用旧协议，见 [清理审计](reliability-test-isolation-cleanup.md)。

## 不可改变的边界

测试通过公开界面、正常 IPC 的产品调用链和外部只读观察验证程序。删除测试工具后，同一输入、设置、权限下的业务决策、范围检查和交付门禁必须相同。

- 业务源码不得识别里程碑、样本 ID、测试场景来授权、选模型、调整超时、跳过校验、模拟成功或改变结果。新增正常产品能力必须对普通用户有同样语义，不能为了通过一个样本写例外。
- `src/main.tsx`、Tauri 启动、环境捕获和业务执行不得加载测试驱动；不添加验收专用 feature、IPC、环境过滤器或隐藏开关。测试工具不得反向成为应用依赖。
- 单元 / 组件测试可放 `*.test.*`；Rust 测试专用注入必须受 `#[cfg(test)]` 保护。端到端工具和独立断言放 `tests/`、`scripts/`，运行记录放外部目录或 `docs/reliability-evidence/`。
- 不从测试工具直接改 Store / 数据库 / 内存状态来设置模型、信任、权限或完成状态；不注入 JavaScript 到被测界面，不替换 `window.confirm`，不伪造 IPC、CLI 完成事件、用量或审查结果。
- 模型、自定义模型、项目、权限、Full Auto、协作者选项和合并确认，通过正常 UI 操作。显式的用户确认属于测试步骤，要记录；外部自动化可以操作正常控件，不能绕过确认处理逻辑。
- 真实验收必须关闭 Debug Provider 并确认不是演示会话。浏览器 Mock、Debug Provider 模拟门禁、演示成功都不能证明真实 CLI 或交付成功。
- 不改变 Git user.name / user.email，不替用户制造作者身份，不手工伪造 Tokage 协作者。通过产品内置选项开启协作者后审查真实提交 trailer。每个验证完成的开发子节点按既有规则本地提交；push 仍需授权。

## 允许的隔离与环境差异

使用已提交代码的独立克隆、session / task worktree。测试不得改主仓库现有工作、`.tokage/` 或个人全局配置。证据、构建产物和依赖安装写到外部克隆。

应用数据隔离使用 Tauri 既有 `--config` 配置叠加：只改变应用标识、应用数据路径及 WebView 数据身份；不修改产品源文件、窗口交互或安全策略。该构建与正式包并非逐字节一致，报告必须附配置差异，不能称为“原发布二进制实测”。发布包验证优先在专用 OS 测试账号 / 机器运行原包。

准备器默认使用持久的独立 `dataStoreIdentifier`。2026-10-21 的首次真实外部构建发现，当前锁定的 `tauri-utils 2.10.1` 在该字段的代码生成中将数组输出成 `Vec<u8>`，使 Rust 编译失败；此前准备器单测并未验证完整原生构建。不得为测试修改产品启动或依赖源码来绕过。若需求不涉及跨重启的前端设置持久性，可显式传入 `--webview-storage ephemeral`，改用标准 Tauri `incognito: true` 隔离 WebView；必须归档配置差异及限制，退出应用后前端设置会丢失。原生应用数据库仍在独立应用数据目录，但不因此推断持久性已通过。需要持久 WebView 验收时，使用专用 OS 账号运行普通包，或先以独立产品依赖升级完成兼容修复及验证。临时模式不是旧驱动或运行时特判。

**应用数据隔离不等于 CLI HOME 隔离。** CLI 仍可能写账号目录、自动记忆、缓存和日志。需要完整文件隔离时使用专用 OS 测试账号 / 机器，并在该账号正常登录；不能通过改主程序关闭记忆、删认证变量或替换 HOME 来隐藏副作用。不得自动复制凭据或输出环境秘密。

依赖可预装、缓存可预热，但须在首次派发前声明安装命令、缓存位置、网络条件和版本。性能 / 冷启动验收不得偷用热缓存。模型 CLI 与账号使用正常配置；任何额外环境覆盖必须提前列明用途和适用结论，不能把非默认运行记成默认通过。测试过程中禁止临时补缓存、改权限或换环境后继续计作同一次首次成功。

## m3a-010 起的操作流程

1. **先登记**：选真实需求，冻结需求、范围、非目标、原有测试、功能验收、模型 / Provider / CLI 版本、产品设置、环境差异、停止条件和证据目录。默认由普通规划界面从需求产生计划；若用户明确指定计划或模型，则按正常 UI 配置并记录，不能由驱动暗改分配结果。
2. **先检查再派发**：工作区相关改动提交；运行 `python3 scripts/check-test-isolation.py`，检查本次差异及应用导入关系。单元测试不包含付费调用。构建 / 检测失败先记录并解决，不得偷改门禁。
3. **外部准备**：运行下面的准备工具。它只克隆已提交版本、复制登记输入并生成标准 Tauri 隔离配置，不启动 App，不调用模型，不安装依赖、不修改账号或 Git 身份。

   ```sh
   python3 scripts/prepare-desktop-test.py \
     --requirement-file docs/reliability-evidence/m3a/m3a-010/request.json
   ```

   `m3a-010/request.json` 必须显式包含 `"protocol": "external-ui-v1"`，并在需求确定后创建，准备工具不会替你虚构第十项需求。阅读输出目录的 `BUILD.txt`，在外部克隆安装依赖、运行隔离检查并用普通 Tauri release 构建；不启用任何验收 feature。开始前比较 source commit、叠加配置与普通构建配置。macOS WebView 的独立数据身份需要系统支持；不支持时使用独立 OS 账号，不能假定已隔离。
4. **正常操作**：启动外部构建，通过 UI 完成初次设置、添加克隆项目、选模型 / 自定义模型、授权及需求发送。记录各关键设置；严禁写 Store / DB 跳过 UI。优先外部 OS 可访问性自动化；工具不可用时人工操作并披露，不能恢复内置注入式驱动。
5. **持续观察**：记录 session / attempt、实际模型事件、流式响应、权限、范围检查、真实命令和状态。允许外部读取日志或 SQLite 一致性备份；不修改正在运行的 DB。运行中不得修改被测源码、门禁、缓存或授权来挽救原样本。
6. **独立验证**：在候选确切提交的独立 checkout 执行原定检查，必要时用同一组断言对旧实现验证可检出缺陷。审查差异、原测试、范围及默认提交身份。需要真实界面行为时保留外部截图 / 可访问性记录或人工观察步骤；单元通过不能替代。
7. **正常交付**：从正常界面确认合并，验证目标提交、durable 状态、真实用量及门禁。无法正常交付则保留失败；人工采纳代码明确记“人工接手”，不能注入成功状态。
8. **归档与提交**：保留失败 / 重试 / 缺失证据，未知值写 null。记录构建版本、隔离配置、模型、设置、外部观察和人工介入，生成哈希清单。验证主仓库与个人配置未被污染。只提交本需求实现、测试和文档。

外部准备仅标记 `prepared-not-executed`；不代表桌面启动、UI 自动化、真实模型或合并已通过。目前没有宣称完成一套跨平台无人值守外部 UI 驱动。若外部自动化受限，采用可复核的人工 UI 步骤；若关键证据仍无法取得，标记 blocked / untested，不能以测试便利为由修改产品。

## 失败、辅助和历史口径

每次尝试从发送真实需求起保留连续记录；同一需求重试不增加需求数。连续两次同因失败停止重复付费调用，外部观察者执行停止操作，不在业务中加入里程碑特判。环境修复后用新 attempt / 新运行目录重新验收，保留之前失败。

常规预定审查和正常用户授权步骤按原约定记录；测试中改业务、提供实质解法、改计划关键部分、修环境救场或手动采纳合并属于相应辅助 / 接手。费用未知不写零。不自动推断同模型、同版本或默认配置下的普遍可靠性。

1–9 的原始证据和当时的分类不重写，不追认新协议通过。从第十项开始记录 `protocol: external-ui-v1`；旧样本为 `legacy-internal-driver`，新旧协议分开统计，可保留连续需求总数，不能将旧五项自主交付改称“普通默认配置无注入验收通过”。

## 回归检查

- `python3 scripts/check-test-isolation.py`：阻止已知验收钩子、里程碑运行时特判、测试环境补丁及前端反向导入测试目录。
- `python3 -m unittest discover -s scripts -p test_test_isolation.py`：验证旧入口不产生副作用、准备器拒绝污染环境和脏源码、配置和提交不被改写。
- `npm run typecheck`、`npm test`、`npm run check:i18n`、`npm run build`，以及与变更相关的 Rust / 原生构建。统一本地入口 `npm run verify:reliability` 包含隔离检查，不自动付费；前端最多两个 worker，Rust 两个编译 job / 测试线程，测试集合和断言不变。真实样本在派发前冻结资源参数。
- 静态防线只针对已知模式，不能代替人工审查。新增测试设施必须审查“是否进入应用依赖、是否改变业务、是否影响个人配置”，不得通过改名或添加白名单绕过。

旧 `run-m3a-desktop.py`、`run-live-desktop.py/.sh`、`run-m2b-desktop.sh`、`run-m2g-crash.py`、`run-m2g-desktop.sh` 已停用，执行即失败退出；`verify-reliability --mode live` 不再能够通过旧驱动发送模型请求。历史版本可通过 Git 回溯，仅用于审计，不作为未来执行入口。

## 正式 CLI 入口的验收

2026-10-21 用户明确暂停第十项并另行授权完整 Tokage CLI 产品开发。`cli/` 是正式公开产品入口，不是桌面注入驱动；正常用户和测试使用同一命令语义、原生适配器、授权摘要、范围检查、门禁与精确合并。CLI 自身开发的离线测试可以通过公开 `--provider-path` 指定测试目录中的协议 fixture；产品不可识别 fixture，离线结果不得记为真实模型通过。隔离静态检查覆盖 `cli/src`。

恢复真实样本前另行冻结入口及协议：CLI 验收须通过公开 create/plan/approve/execute/merge 等命令，记录显式授权、实际模型、流式事件及真实 Git 交付，不能直接改 run.json/事件来完成状态。故障注入仅限离线测试文件及其独立临时状态。旧 `external-ui-v1` 登记不自动变成 CLI 通过；桌面 UI 行为仍须外部正常 UI 观察。独立 CLI 数据目录仍不能隔离 CLI HOME。
